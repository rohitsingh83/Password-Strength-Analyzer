# Deployment guide

Three supported deployments, from simplest to most involved. All three are
free and none of them requires a credit card.

| Option | Best for | Effort | Backend |
|---|---|---|---|
| **1. GitHub Pages (static build)** | Portfolio, demos, coursework submission, placement links | 10 minutes | None — the engine runs in the browser |
| **2. Local Flask server** | Report screenshots, API demonstration, viva | 2 minutes | Python |
| **3. Managed host (Render / Railway / Fly.io)** | Showing "I deployed a backend too" | 20 minutes | Python behind HTTPS |

---

## Option 1 — GitHub Pages (recommended for the placement link)

The whole engine is plain JavaScript in `frontend/js/`, so the site analyses
passwords **without any server and without any network request**. That is both a
privacy feature and the reason it is free to host.

### 1.1 One-time repository setup

```bash
git init
git add .
git commit -m "Initial commit: password strength analyzer, engine, tests and docs"
git branch -M main
git remote add origin https://github.com/<your-username>/Password-Strength-Analyzer-Security-Tool.git
git push -u origin main
```

### 1.2 Enable Pages

1. Open the repository → **Settings** → **Pages**.
2. **Source**: *Deploy from a branch*.
3. **Branch**: `main` and folder **`/ (root)`** → **Save**.
4. Wait ~60 seconds. The URL is
   `https://<your-username>.github.io/Password-Strength-Analyzer-Security-Tool/`.

> ### Why not serve `/frontend` as the Pages folder?
> GitHub Pages can serve either the repository root or a `/docs` folder. The
> project keeps the app at `frontend/index.html` for local development
> (`python backend/app.py` serves it), so the root `index.html` is a small
> redirect/host page that loads the app. See **1.4** if you prefer the simpler
> layout.

### 1.3 What must be in the repository for the page to work

```
index.html                      (root)         -> loads frontend/ or redirects
.nojekyll                                      -> tells Pages to serve files as-is
frontend/index.html                            -> the single-page app
frontend/css/styles.css
frontend/js/app.js  charts.js  hashdemo.js  engine.js
frontend/js/data/*.js                          -> GENERATED, must be committed
```

Two Git-specific traps worth knowing (both are stated in `.gitignore` as
comments, not as exclusions):

1. **Do not ignore `frontend/js/data/`.** Those files are generated by
   `scripts/build_frontend_data.py`, and Pages has no build step, so the generated
   output *must* be committed. If the site loads but every analysis says
   "dictionary unavailable", this is why.
2. **Underscore-prefixed directories are skipped** by Jekyll. This project does
   not use any, but `.nojekyll` is included so nothing is transformed.

If you change `data/*.txt`, regenerate and commit the browser copies:

```bash
python scripts/build_frontend_data.py
python scripts/generate_fixtures.py      # keep the parity fixture in step
git add frontend/js/data tests/fixtures && git commit -m "Regenerate browser data files"
```

### 1.4 Alternative layout: publish `/docs` instead

If you would rather publish only the app and keep the repository tidy:

```bash
mkdir -p docs/app
cp -r frontend/* docs/app/
```

Then set Pages to **`main` / `/docs`** and commit a `docs/index.html` that
redirects to `app/index.html`. The default layout in this repository (root
`index.html`) is preferred because it also works when the repo is zipped and
opened locally.

### 1.5 Verify the deployment

* Open the Pages URL in a private window.
* Open DevTools → **Network** and analyse a value: the panel stays **empty** and
  the header badge reads *"Offline · Private"*.
* Open DevTools → **Application**: no `localStorage`, no cookies, no cache
  entries created by the app.
* Run `python scripts/capture_screenshots.py --url https://<your-pages-url>/` to
  capture screenshots straight from the live site.

## Option 2 — Local Flask server

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # optional: edit HOST/PORT/ANALYTICS_ENABLED

python backend/app.py              # http://127.0.0.1:5000
```

Production-ish local run (no reloader, no debug):

```bash
FLASK_DEBUG=0 ANALYTICS_ENABLED=1 python backend/app.py
```

FastAPI variant (same services, different framework):

```bash
pip install fastapi uvicorn
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Smoke test:

```bash
curl -s http://127.0.0.1:5000/api/health | python -m json.tool
curl -s -X POST http://127.0.0.1:5000/api/analyze \
     -H "Content-Type: application/json" \
     -d '{"password":"Password123!"}' | python -m json.tool
```

## Option 3 — Managed host (Render / Railway / Fly.io)

The Flask app is a standard WSGI application, so any Python host works.

**Build**
```
pip install -r requirements.txt
```

**Start**
```
gunicorn --workers 2 --bind 0.0.0.0:$PORT backend.app:create_app()
```

`backend/app.py` exposes a factory (`create_app`) and a module-level `app`, so
both `backend.app:app` and `backend.app:create_app()` work.

**Environment variables**

| Variable | Production value | Why |
|---|---|---|
| `HOST` | `0.0.0.0` | Required by container hosts |
| `PORT` | provided by the host | Most hosts inject it |
| `FLASK_DEBUG` | `0` | Never run debug mode in public |
| `ANALYTICS_ENABLED` | `1` or `0` | `0` disables all storage |
| `DATABASE_PATH` | a path on the persistent volume | Otherwise analytics reset on redeploy |
| `MAX_CONTENT_LENGTH` | `65536` | Rejects oversized bodies early |

**Before you call it done**

- [ ] HTTPS works and HTTP redirects to it (most hosts do this automatically).
- [ ] `FLASK_DEBUG=0`.
- [ ] Rate limiting is real: the in-process token bucket is per-worker, so with
      more than one worker move it to a shared store (Redis) — see
      `backend/routes/analyze.py`.
- [ ] The proxy is not logging request bodies.
- [ ] A retention policy exists for the metadata table (for example delete rows
      older than 90 days) if analytics is enabled.
- [ ] You have **not** pointed the tool at real user passwords. It is a learning
      tool: keep the copy on the deployment page saying "use synthetic values".

## The standalone single file

For an offline demo (a lab machine with no network, or a USB stick):

```bash
python scripts/build_standalone.py
# -> Password-Strength-Analyzer-standalone.html   (~273 KB, everything inlined)
```

Double-click it. No server, no internet, same engine. Useful when a viva machine
blocks network access or when the marker wants a single artefact.

## Continuous integration

`.github/workflows/ci.yml` runs on every push and pull request:

1. `python -m pytest -q` — engine, API, privacy and scope tests.
2. `node tests/js/run_parity_test.js` — JavaScript/Python engine parity.
3. `python scripts/generate_fixtures.py` then `git diff --exit-code` — fails if
   the fixture was not regenerated after an engine change.
4. `python scripts/build_standalone.py` — fails if the shipped single-file build
   is stale.

Reproduce it locally in one line:

```bash
python -m pytest -q && node tests/js/run_parity_test.js && python scripts/build_standalone.py
```

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Pages shows a 404 | Pages not enabled, or the wrong branch/folder selected | Settings → Pages → `main` / `/ (root)` |
| Page loads but styling is broken | `frontend/css/styles.css` not committed | `git status` — commit the file |
| "Dictionary unavailable" in the UI | `frontend/js/data/*.js` missing | `python scripts/build_frontend_data.py` and commit |
| `ModuleNotFoundError: backend` | Running from the wrong directory | Run commands from the repository root |
| `Address already in use` | Port 5000 is taken | `PORT=5001 python backend/app.py` |
| `sqlite3.OperationalError: unable to open database file` | `DATABASE_PATH` points at a missing directory | Create it, or use the default |
| Playwright: `libnspr4.so: cannot open shared object file` | Linux host missing browser libraries | `sudo apt-get install -y libnspr4 libnss3 libasound2t64 ...` (list in `docs/SCREENSHOTS.md`) |
| CI fails with "fixture is stale" | An engine change was committed without regenerating | `python scripts/generate_fixtures.py` and commit |
| CI fails on the parity test | The JS engine drifted from Python | Fix `frontend/js/engine.js` (see "Parity pitfalls" in `CONTRIBUTING.md`) |
